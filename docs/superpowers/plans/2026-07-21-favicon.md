# Favicon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a browser-tab icon (outline-checkbox SVG) to the app as an inline `data:` URI in `index.html`.

**Architecture:** One `<link rel="icon">` line in the `<head>` of `index.html`, carrying the whole SVG as a URL-encoded `data:image/svg+xml` URI. No new files, no script changes — the app stays a single self-contained file.

**Tech Stack:** Plain HTML; existing Node test suites for regression only.

**Spec:** `docs/superpowers/specs/2026-07-21-favicon-design.md`

## Global Constraints

- `index.html` remains the only app file — the favicon must be inline, never a sibling asset.
- Do not touch the `// ===== CORE START =====` / `// ===== CORE END =====` / `// ===== APP =====` marker comments or any script content.
- Icon strokes use the app accent color `#2563eb`, written `%23` inside the data URI.
- Data URI stays URL-encoded UTF-8 (not base64); single quotes inside, double quotes around `href`. Literal spaces inside the URI are accepted (Chromium-only app).

### Task 1: Inline SVG favicon in index.html

**Files:**
- Modify: `index.html:5` (insert one line immediately after `<title>Org Todo</title>`)

**Interfaces:**
- Consumes: nothing from other tasks (this is the only task).
- Produces: nothing consumed elsewhere — static markup only.

This is static markup, so there is no unit test to write first (CORE is untouched). The test cycle is: make the edit, verify the markup landed exactly, run both existing suites to prove no regression.

- [ ] **Step 1: Insert the favicon link**

In `index.html`, directly after the line `<title>Org Todo</title>` (line 5), insert this single line:

```html
<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 16 16'><rect x='1' y='1' width='14' height='14' rx='3.5' fill='none' stroke='%232563eb' stroke-width='1.8'/><path d='M4.4 8.2 L7 10.8 L11.8 5.6' fill='none' stroke='%232563eb' stroke-width='2' stroke-linecap='round' stroke-linejoin='round'/></svg>">
```

The `<head>` then reads:

```html
<head>
<meta charset="utf-8">
<title>Org Todo</title>
<link rel="icon" href="data:image/svg+xml,<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 16 16'><rect x='1' y='1' width='14' height='14' rx='3.5' fill='none' stroke='%232563eb' stroke-width='1.8'/><path d='M4.4 8.2 L7 10.8 L11.8 5.6' fill='none' stroke='%232563eb' stroke-width='2' stroke-linecap='round' stroke-linejoin='round'/></svg>">
<meta name="viewport" content="width=device-width, initial-scale=1">
```

- [ ] **Step 2: Verify the markup landed exactly once**

Run:

```bash
grep -c 'rel="icon"' index.html
```

Expected output: `1`

- [ ] **Step 3: Run the unit tests**

Run:

```bash
node --test 'tests/*.test.mjs'
```

Expected: all tests pass (`fail 0`). Note the quotes — a bare directory arg does not work.

- [ ] **Step 4: Run the browser e2e test**

Run:

```bash
node tests/ui-e2e.mjs
```

Expected: exits 0 with its pass summary (needs Google Chrome; set `CHROME_BIN` to override).

- [ ] **Step 5: Commit**

```bash
git add index.html
git commit -m "feat: inline SVG favicon (outline checkbox in accent blue)"
```
