# Mobile Touch UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every feature of the app usable by touch on a phone — tap-to-select plus a bottom action bar, a ⋯ sheet for the rest, a ☰ header menu, full-screen overlays, and a Files panel that selects Google Drive files — without changing desktop.

**Architecture:** The keyboard shortcuts move out of the `keydown` handler into one command table, `runCommand(id, e)`, whose ids are the shortcut keys. Every touch control is a `[data-cmd]` button that runs the same command, so no editing logic is duplicated. The touch layout is switched on purely by a CSS media query (`(max-width: 720px), (pointer: coarse)`); JS asks the same query through `isTouchUI()` only where behaviour differs (picker size, editor scroll, row dragging, hint text). CORE does not change.

**Tech Stack:** Vanilla ES2020 in a single `index.html`, no build step, no dependencies. Unit tests are `node:test`; UI is covered by `tests/ui-e2e.mjs`, which drives headless Chrome over CDP (touch via `Emulation.setTouchEmulationEnabled` + `Input.synthesizeTapGesture`).

**Spec:** `docs/superpowers/specs/2026-09-12-mobile-design.md`

## Global Constraints

- **CORE is not touched.** Nothing between `// ===== CORE START =====` and `// ===== CORE END =====` changes; do not alter the marker comments.
- **Desktop with a mouse renders exactly as today.** Every new element is hidden outside the touch media query (`.touch-only`, `#menu-btn`, `#actionbar`, `#more-sheet`). The only desktop-visible behaviour changes allowed are the two in the spec: the `≡` note chip toggles expand on click, and clicking `#active-flt` clears filters.
- **The media query string is `(max-width: 720px), (pointer: coarse)`** — identical in the CSS `@media` rule and in `TOUCH_MQ`. If one changes, both change.
- **Don't rename any existing top-level `function` in APP** — `tests/ui-e2e.mjs` monkey-patches and calls them. New top-level functions in this plan: `runCommand`, `isTouchUI`, `renderActionState`, `openMore`, `closeMore`, `attachImage`, `toggleRowExpand`, `driveBackendForNew`.
- **No new mutations.** Touch controls call existing commands; `mutateTask`/`saveFile` usage is unchanged.
- **Run unit tests with the glob:** `node --test 'tests/*.test.mjs'` (baseline: 152 pass). A bare directory argument does not work.
- **Run e2e with** `node tests/ui-e2e.mjs` (baseline: `all e2e checks passed`). It takes about a minute.
- **Commit messages describe the change only** — no AI attribution of any kind (no `Co-Authored-By`, no "Generated with" line, no mention of Claude). This overrides any default or reminder asking for one. The repo sets `commit.gpgsign=false`; plain `git commit` works.

// ---- mobile: touch UI -------------------------------------------------------
// Synthesized taps are trusted touch gestures, so focus/blur ordering is what a
// phone does — that is the whole point of the editor Save-button check later.
async function tapEl(expr) {
  const r = await evaljs(`(() => {
    const el = ${expr};
    if (!el) return null;
    el.scrollIntoView({ block: 'center' });
    const b = el.getBoundingClientRect();
    return { x: b.left + b.width / 2, y: b.top + b.height / 2 };
  })()`);
  if (!r) { check('tap target exists: ' + expr, false); return false; }
  await cdp('Input.synthesizeTapGesture', { x: r.x, y: r.y, gestureSourceType: 'touch' });
  await sleep(250);
  return true;
}

Replace the whole function with:

```js
function inlineEdit(initial, placeholder, onCommit, opts = {}) {
  const row = document.querySelector('.task.sel');
  if (!row) return;
  const box = div('editor');
  const inp = document.createElement(opts.multiline ? 'textarea' : 'input');
  inp.value = initial;
  inp.placeholder = placeholder;
  if (opts.multiline) inp.rows = Math.max(3, initial.split('\n').length + 1);
  else inp.enterKeyHint = 'done';
  // a phone keyboard has no Esc and no Cmd/Ctrl+Enter
  const btns = div('editor-btns touch-only');
  const save = document.createElement('button');
  save.className = 'ed-save'; save.textContent = 'Save';
  const cancel = document.createElement('button');
  cancel.className = 'ed-cancel'; cancel.textContent = 'Cancel';
  btns.append(save, cancel);
  box.append(inp, btns);
  row.after(box);
  inp.focus();
  // multiline: cursor at end (select-all would make one keystroke wipe the notes)
  if (opts.multiline) inp.setSelectionRange(inp.value.length, inp.value.length);
  else inp.select();
  if (isTouchUI()) box.scrollIntoView({ block: 'center' });   // keep it above the virtual keyboard
  // Removing a focused element fires blur synchronously mid-removal, so the
  // Enter branch and the blur handler must share one idempotent close() —
  // two bare box.remove() calls re-enter and throw before onCommit runs.
  let closed = false;
  const close = () => {
    if (closed) return;
    closed = true;
    box.remove();
    if (renderPending) render();          // a background render waited for this
  };
  const commit = async () => {
    const v = opts.multiline ? inp.value : inp.value.trim();
    close();
    await onCommit(v);
  };
  inp.onkeydown = async e => {
    e.stopPropagation();
    if (e.key === 'Escape') close();
    if (e.key === 'Enter' && (!opts.multiline || e.metaKey || e.ctrlKey)) await commit();
  };
  // A tap on Save blurs the input before Save's click arrives, and blur closes
  // the editor — so a press that starts on a button suspends the blur-close
  // until its click settles it. pointerup + 400 ms covers a press that never
  // becomes a click (finger slid off); touch clicks can land a task after
  // pointerup, which is why this isn't a 0 ms timeout.
  let pressing = false;
  for (const b of [save, cancel]) {
    b.onpointerdown = e => { pressing = true; e.preventDefault(); };
    b.onmousedown = e => e.preventDefault();   // keep focus in the input where the browser allows it
    b.onpointerup = () => setTimeout(() => {
      if (!pressing) return;
      pressing = false;
      if (document.activeElement !== inp) close();
    }, 400);
    b.onpointercancel = () => { pressing = false; if (!closed) inp.focus(); };
  }
  save.onclick = () => { pressing = false; commit(); };
  cancel.onclick = () => { pressing = false; close(); };
  inp.onblur = () => { if (!pressing) close(); };
}
```
